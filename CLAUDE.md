# Working on Muna

The owner is not a programmer and works from a phone. Do everything for them; only ask when there is truly no workaround.

## Standing instruction: always ship to `main`

The owner has explicitly and permanently authorized this: **after every change, merge it into `main`** so the site updates. Do not wait to be asked.

1. Commit on the session's development branch and push it.
2. Open a pull request into `main`, then merge it (merge commit).
3. Confirm the "Deploy to GitHub Pages" run (Actions) finished with success, and tell the owner.
4. Bump `VERSION` and add a `CHANGELOG` entry in `js/version.js` (and the cache name in `sw.js`) for every user-visible change, so the owner can see on the Updates page that it arrived.

## Where things are

- Static web app, no build step: `index.html`, `css/app.css`, `js/*.js`. Hosted on GitHub Pages: https://jareddarkus.github.io/Muna/
- Supabase project `vqtepepiagjsljvauqyn` (auth, database, realtime, storage, `push` edge function). Migrations live in `supabase/migrations/`.
- Icons are generated by `scripts/build-icons.mjs` from `@tabler/icons`.
- Design: white/black UI, 11-color accent palette, Lexend (regular for text, bold for titles), everything rounded, ease-out motion.
